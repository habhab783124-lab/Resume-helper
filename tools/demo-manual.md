# 拾阶求职工作台 · 演示操作手册

> 这份手册是给**在演示机上操作的人**看的，不需要懂开发。
> 整个演示包不依赖网络、不需要安装任何东西（JDK、Maven、Node 全都不用装）。

---

## 一、包里有什么

```
拾阶-演示包\
├── 启动演示.cmd              ← 双击这个就行
├── 演示操作手册.md            ← 你正在看的这份
├── app\
│   ├── resume-helper-backend-0.1.0-SNAPSHOT.jar   后端 + 前端（一个进程全包了）
│   └── webapp\                                     前端页面
└── jre\                      ← 便携版 Java 17，不用在那台电脑上装 Java
```

**总大小约 168 MB**（其中便携 JRE 占 125 MB）。

关键设计：**后端自己就把前端页面一起提供了**，所以只有一个进程、一个端口。
不需要装 Node、不需要装 Maven、不需要联网、不需要配任何东西。

> 想再小一点？把 `jre\` 删掉可以降到 43 MB，但要求目标电脑已经装了 Java 17+。

## 二、演示前一定要先演练一遍（5 分钟）

> ⚠️ **这一步不能省。** 在**同一台**将要用来演示的电脑上做。

1. **把整个 `拾阶-演示包` 文件夹拷到那台电脑的桌面**
   （**不要直接在 U 盘上运行**——读盘慢，而且演示中途被碰掉 U 盘就完了）
2. 双击 **`启动演示.cmd`**
3. 会弹出一个黑窗口，等它显示 `Ready.`
   （通常 5～10 秒；第一次可能慢一点）
4. 浏览器会**自动打开** `http://localhost:8080/`
5. 用演示账号登录：

   | 邮箱 | `demo@resume-helper.cn` |
   |---|---|
   | 密码 | `ResumeDemo2026!` |

6. 点左侧导航的 **「岗位匹配」**
   → 应该看到 **12 张带匹配度的岗位卡片**（分数 100 / 93 / 84 …）
7. 关掉那个**最小化的**服务窗口，结束演练

**如果第 6 步看到了 12 张卡片，就说明一切正常，可以放心演示。**

## 三、演示当天怎么操作

1. 双击桌面上的 **`启动演示.cmd`**

## 四、演示脚本（建议照着点）

> 四个功能都是**真的接了后端**，不是静态页面。
> 建议顺序：材料整理 → 个人资料 → 简历工作台 → 岗位匹配 → 模拟面试，
> 正好是一条完整的求职链路。

### 0. 先决定要不要填 AI token（可选，但效果差别很大）

在 **「岗位匹配」页顶部**有一个填 API Key 的地方。填上自己的 DeepSeek token 之后，
四个页面里涉及大模型的功能才会真正工作：

| 功能 | 有 token | 没有 token |
|---|---|---|
| 材料整理 → 自动识别简历内容 | 自动抽出教育 / 实习 / 项目 / 技能 | **明确提示无法自动识别**，可改用「粘贴文本」或手动填 |
| 简历工作台 → AI 改写建议 | 针对岗位描述逐条给建议 | 提示没有 token，**不编造建议**，仍可手动编辑和打印 |
| 岗位匹配 → 匹配解释、智能体 | 自然语言理由 + 多轮检索轨迹 | 退回规则打分与规则文案，**仍然可用** |
| 模拟面试 → 出题与追问、面试报告 | 完整可用 | 提示需要 token |

**这个设计本身就是可以讲的一个点**：没有 token 时系统会**如实说明能力受限**，
而不是用规则硬凑一份看起来完整的结果。

> ⚠️ token 只存在浏览器里（关掉标签页即失效），后端不落库、不打日志。
> 演示时注意**别被投屏拍到**。

### 1. 登录页
输入演示账号，点登录。

### 2. 工作台
- 展示"求职准备度 68%"的环形图
- 指标卡："本周匹配岗位 08 个" ← **这个数字是从后端实时取的**
- 往下滚，**「与你经历相近的岗位」**里已经有 **3 个真实岗位**了

### 3. 材料整理 —— 功能一
- **拖一份 PDF / DOCX 到虚线框**（或点它选文件，也可以直接粘贴一段文字）
- 如果填了 token：右边会列出**识别出的教育 / 实习 / 项目 / 技能**，
  **每一条都带「原文片段」**——这是可以重点讲的：
  > 每条识别结果都能对回原文，模型编造的内容会被直接丢掉。
- 左边是**原文对照**，可以逐条核对
- 改完点 **「确认并保存为我的资料」** → 这份资料会立刻被后面的页面用上
- 上传**扫描版 PDF**（没有文字层的）时不会报错，而是提示改用「粘贴文本」——
  > 那是文件的问题，不是产品坏了。

### 4. 个人资料 —— 功能一的下半段
- 抬头、姓名、电话、邮箱、技能、教育经历、经历**都是从刚才的材料里来的**
- 点右上 **「编辑资料」** 可以改，改完保存
- 注意右上角的 **「档案完整度」**：它是按**实际填了几个字段**算的，
  **不是写死的百分比**——删掉一个字段它真的会掉
- 技能那一块**刻意不显示"熟练 / 熟悉 / 了解"**：
  > 画像里没有这个信息，编一个出来会让用户以为系统真的评估过。

### 5. 简历工作台 —— 功能四（建议重点演示）
- 左侧是编辑器，右侧是 **A4 预览**，改左边的字右边**立刻跟着变**
- 抬头已经带上了姓名 / 电话 / 邮箱
- **在「定向到具体岗位」里粘一段招聘网站的 JD** → 点 **「让 AI 给改写建议」**
  → 会出现逐条建议卡片，每条显示 **原文 / 建议稿 / 为什么改**
  > 建议**不会自动覆盖原文**，要点「采纳这条」才写进简历。
  > 而且提示词里明确禁止编造数字——原文没写响应时间，它就不会写"降低 60%"；
  > 缺数据的地方会用 `[!补充具体数据]` 占位，让你自己填。
  > **这一点被问到一定要讲**：简历是投出去的，编造的数字用户面试时会被问穿。
- 点 **「保存版本」** → 下面「已保存的版本」里多一条，可以随时**载入**回来
  > 投不同岗位可以各存一版
- 点右上 **「打印 / 导出 PDF」** → 在打印对话框里选「另存为 PDF」
  > 打印时会自动隐藏所有按钮和编辑器，**只留 A4 纸面**

### 6. 岗位匹配 —— 功能二（⭐ 这个也重点）
- **12 张岗位卡片**，每张都有：
  - 匹配度分数（右上角）
  - 一句话匹配理由（"技能命中 4/4 项。"）
  - 技能标签、薪资、经验要求
- **搜索框**输入 `Java` → 列表实时过滤
- 点 **「城市：上海」/「经验」/「排序」** 三个按钮 → 每点一下切换到下一个取值，列表跟着变
- 点 **「让智能体去找」** → 页面上会出现**执行轨迹**：
  ```
  第 1 轮  search_jobs   关键词「后端开发」命中 6 个岗位
  第 2 轮  search_jobs   关键词「Java」命中 6 个岗位
  第 3 轮  finish        已收集 6 个候选岗位，按贴合度排序后返回
  ```
  ← **这是"智能体"最直观的展示，一定要点**
  > 它是自己规划关键词、检索、看结果、再决定换词扩检的循环，
  > 每一步都打在页面上，可以回放。
- 点右上角 **「＋ 粘贴岗位描述」** → 随便粘一段 JD → 点「导入并匹配」
  → 会立刻算出匹配度并插到列表最前面
  > 这也是**合规上的兜底**：不爬招聘网站，用户自己粘 JD 一样能完成匹配。
- 点卡片右下角 **「收藏岗位」** → 变成"已收藏"

### 7. 模拟面试 —— 功能三
- 选题量（3 / 5 / 8 题）→ 点开始
- AI 根据**你的简历**提问，一问一答；有追问
- 答完点结束 → 生成**面试报告**（逐题点评 + 总评 + 建议）
- 刷新页面能恢复进度

## 五、出问题了怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击没反应，或窗口一闪而过 | 被安全软件拦了 | 右键 → **以管理员身份运行** |
| 黑窗口显示 `[ERROR] Java not found` | 便携 JRE 缺失或被杀毒软件删了 | 确认 `jre\bin\java.exe` 存在 |
| 浏览器打开是"无法访问此网站" | 服务还在启动 | **等 5 秒刷新页面** |
| 黑窗口显示的 Port 不是 8080 | 8080 被别的程序占了，脚本自动换了端口 | 用黑窗口里显示的那个端口，例如 `http://localhost:8081/` |
| 岗位页显示 **"请求失败（HTTP 405）"** 或列表为空 | 服务没起来，或者那个最小化的服务窗口被关掉了 | 确认服务窗口还在，然后刷新页面 |
| 页面能开但岗位列表空 | 同上 | 刷新；还不行就重启启动器 |
| 材料页说"没有 AI token，无法自动识别" | 这是**预期行为**，不是故障 | 在岗位页顶部填 token；或演示「粘贴文本」 |
| 黑窗口里中文是乱码 | 控制台编码 | **不影响功能**，忽略即可 |

### 应急手段（按顺序试）

**① 启动器完全跑不起来 → 手动开命令行**

按 `Win + R`，输入 `cmd`，回车，然后：

```
cd /d "%USERPROFILE%\Desktop\拾阶-演示包\app"
..\jre\bin\java.exe -jar resume-helper-backend-0.1.0-SNAPSHOT.jar --server.port=8080
```

看到 `Tomcat started on port 8080` 之后，浏览器打开 <http://localhost:8080/>

**② 便携 JRE 坏了 → 用那台电脑自己的 Java**

如果那台机器装了 Java 17 或更高版本：

```
cd /d "%USERPROFILE%\Desktop\拾阶-演示包\app"
java -jar resume-helper-backend-0.1.0-SNAPSHOT.jar --server.port=8080
```

**③ 端口全被占 → 换一个**

在上面命令末尾把 `--server.port=8080` 改成 `--server.port=9000`，浏览器也用 `http://localhost:9000/`。

## 六、几个重要提醒

1. **不要在 U 盘上直接运行**——拷到本地磁盘再跑
2. **演示结束要关闭那个最小化的服务窗口**，否则端口会一直被占着
3. **不联网也能演示**——除了「填了 token 后调用大模型」那几处，
   其余全部离线可用（岗位数据、匹配打分、简历生成都是本地的）
4. **演示账号是写死在前端代码里的公开账号**（任何人都能从 GitHub 上看到），
   所以**不要在这个演示环境里填任何真实个人信息**（真实姓名 / 手机号 / 邮箱都别填）。
   这个包是发给同学试用的，填了就会留在那台电脑的 `app\data\` 目录里
5. 岗位数据是**课程演示用的编造数据**，页面上也这么标注了——被问到时要如实说明
   （真实招聘来源因**合规原因**未接入，改用「演示岗位库 + CSV + 粘贴 JD」兜底）

## 七、如果被问"为什么不用那个 Vercel 网址"

可以这样回答：

> Vercel 上部署的是纯前端静态页面。它要拿到真实数据，必须能访问到一个**公网的后端服务**，
> 而我们的后端跑在本地（`localhost`）——Vercel 的服务器和访问者的浏览器都到不了它，
> 而且 Vercel 是 HTTPS 页面，浏览器不允许它请求 `http://` 的接口。
>
> 所以我们采用**本地一体化运行**：后端同时提供页面和接口，同源、零依赖，演示时最稳定。
> 如果后续要做公网版本，需要把后端也部署到公网（HTTPS）并配置 CORS 白名单——
> 这部分代码已经预留好了（前端的 `VITE_API_BASE_URL`、后端的 `app.job.cors`）。

## 八、同学想自己改代码怎么办

这个包只能**用**，不能改。要看代码 / 自己动手改，用 Git：

```
git clone https://github.com/habhab783124-lab/Resume-helper
cd Resume-helper\backend
mvn spring-boot:run

# 另开一个终端
cd Resume-helper\frontend
npm install
npm run dev
```

要求：**JDK 17 + Maven + Node 18+**。
第一次跑 Maven 会联网下载约 200 MB 依赖。更细的说明见仓库根目录的 `README.md`。
