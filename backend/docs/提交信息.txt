feat(job): 新增岗位来源与匹配模块（功能二）

实现产品方案 3.C「岗位搜索和匹配」，对应功能二需求「有一个智能体去网上找适合用户的岗位」。

数据源（可插拔）
- JobSource SPI + JobSourceRegistry：聚合、单来源失败隔离、跨来源去重
- 内置演示岗位库（兜底）+ CSV 岗位库（人工整理）+ 粘贴 JD 导入
- 新增来源只需实现接口并注册 Bean，智能体与检索逻辑无需改动

岗位检索智能体
- ReAct 循环：规划关键词 -> 聚合检索 -> 观察命中 -> 换词扩检 -> 排序解释
- 执行轨迹随响应返回，前端可渲染成时间线
- 用文本行协议而非各厂商 function calling：用户自带 token 意味着模型不固定

匹配与差距分析
- 六维加权打分（技能 45 / 方向 20 / 城市 15 / 经验 10 / 学历 5 / 薪资 5），完全可解释
- 技能差距报告：优势、差距、可执行的补强建议
- 规则分保证大模型不可用时功能依然完整，AI 只补充自然语言解释
- 强制响应 scoreNotice：匹配度是贴合程度，不是录取概率

AI 接入
- 用户自带 token 走请求头（X-AI-Api-Key / X-AI-Base-Url / X-AI-Model），服务端配置兜底
- 按请求构造客户端，不注册单例，避免多用户之间 token 串号
- 密钥不落日志（只允许 maskedKey）；JDK HttpClient，不引第三方 SDK

三层降级保证（产品方案 11 风险兜底）
- 无 token / 鉴权失败 / 超时 -> 离线替身按规则继续跑，notes 里说明原因
- 关键词过窄 -> 注册中心放宽为按硬条件返回
- 所有来源失败 -> 演示岗位库兜底，岗位页不会空白

架构
- core 层（domain/source/match/agent/store）零框架依赖，只依赖 JDK，可脱离容器验证
- Spring 只出现在 api/service/config
- 岗位模块零数据库依赖，不会被队友的 MySQL 进度阻塞；表结构见 db/schema.sql

验证
- tools/verify.ps1：用 JDK 自带 javac 编译全部源码并跑 102 项断言（无需 Maven/数据库/网络）
- tools/smoke-api.ps1：真实 HTTP 冒烟，10 组接口 51 项断言
- src/test 的 JobAgentOfflineDemo 是可执行的规格说明
