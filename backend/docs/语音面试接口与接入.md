# 火山语音面试接入（阶段一：账户与音频兼容性验证）

本文档只覆盖[实施计划](../../docs/superpowers/plans/2026-10-13-interview-voice-volcengine.md)的 Task 1：在写后端适配器之前，先用真实账户把火山两条链路打通，留下可复现的证据。

后端接口、前端录音/朗读、页面接入分别由 Task 3–Task 6 完成，本文档不含接口定义。

## 本期能力

| 能力 | 接口 | 资源 id |
| --- | --- | --- |
| ASR 录音文件识别 | `POST /api/v3/auc/bigmodel/recognize/flash`（录音文件极速版识别 HTTP） | `volc.bigasr.auc_turbo` |
| TTS 语音合成 | `POST /api/v3/tts/unidirectional`（单向流式 HTTP） | `seed-tts-2.0` |

域名统一为 `https://openspeech.bytedance.com`。TTS 输出 MP3，后端消费分块结果拼出完整文件再交给浏览器；ASR 把 WAV bytes 经 Base64 放进 `audio.data`，同步取转写文字，不需要公网录音 URL 或对象存储。

第一版不做：实时对话、WebSocket、流式字幕、打断、声音克隆、评分报告、数据库迁移。官方文档见[录音文件极速版识别](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelrecordingfileLiterecognitionAPI?lang=zh)和[单向流式语音合成](https://docs.volcengine.com/docs/DoubaoVoice/unidirectional-streaming-text-to-speech-http?lang=zh)。

## 前置条件

1. 控制台开通豆包语音，且账户对 `volc.bigasr.auc_turbo` 与 `seed-tts-2.0` 两个资源有权限、有额度。资源权限不等于音色权限：音色还要在该资源下有可用额度，Task 1 就是要确认这两层。
2. API Key 必须来自**语音技术控制台**，不是火山方舟（Ark）大模型 key。两者不通用：方舟 key 以 `ark-` 开头，调语音接口直接返回 HTTP 401，且响应体没有可读错误信息。语音 key 在语音控制台的「设置 → API Key」创建。
   - 新版控制台只需 `X-Api-Key` 一个鉴权头，冒烟脚本和本文档按这个写。
   - 旧版控制台需要 `X-Api-App-Key` 与 `X-Api-Access-Key` 两个头。若账户仍在旧版控制台，冒烟脚本和 Task 3 的适配器都要补这两个头。
3. **不要把 key 写进本文档、仓库或前端环境变量**；只放在环境变量里。仓库已排除 `backend/src/main/resources/application-local.yml`。
4. 本机有 FFmpeg 与 FFprobe 可执行文件，在 PATH 上。本机验证环境为 `ffmpeg 8.1` / `ffprobe 8.1`（macOS Homebrew，`/opt/homebrew/bin/`）。
5. 本机有 Python 3.8+，冒烟脚本只用标准库。

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `VOLC_SPEECH_API_KEY` | 语音服务密钥，必填。缺失时冒烟脚本立即退出，不发任何请求 |
| `VOLC_TTS_SPEAKER` | 合成音色，默认 `zh_female_vv_uranus_bigtts` |
| `VOLC_ASR_RESOURCE_ID` | 识别资源 id，默认 `volc.bigasr.auc_turbo`（官方文档示例值）。资源以账号实际授权为准，见下一节 |

以上独立于现有文本模型的 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`。不要把方舟文本模型密钥当作语音服务密钥使用，两者互不覆盖。后端正式配置在 Task 3 加入 `app.interview.speech.*`，同样独立于岗位模块的 Ai 配置，其中 `asr-resource-id` 需按账号授权填写。

## 冒烟脚本

`backend/tools/speech-smoke.py`。做的事只有两件：合成一句固定面试题并落地 MP3，再把这段音频送去识别并打印文本。每次调用都带新的 `X-Api-Request-Id`，TTS 与 ASR 超时分别为 30 秒和 60 秒。

```bash
# 缺 key：立即退出，打印“请配置 VOLC_SPEECH_API_KEY”，退出码 1，不发请求
python3 backend/tools/speech-smoke.py

# 完整链路：合成 → 落地 MP3 → 识别
export VOLC_SPEECH_API_KEY='你的 key'
python3 backend/tools/speech-smoke.py

# 换音色，或在控制台音色列表里挑一个自己有权使用的
export VOLC_TTS_SPEAKER='zh_female_vv_uranus_bigtts'

# 只识别本地录音，不合成
python3 backend/tools/speech-smoke.py --asr-file out.wav

# 指定 MP3 落地路径
python3 backend/tools/speech-smoke.py --output ~/Downloads/question.mp3
```

成功时输出四行：TTS 字节数与耗时、音频输出路径、ASR 字数与耗时、识别文本。合成的 MP3 应可直接播放，识别文本应包含 Redis 与 Spring Boot 项目缓存的含义。固定样例只验证专有名词能不能被识别出来，不是准确率基准。

密钥只从环境变量读取，不写文件、不打印、不出现在任何输出或错误信息里。脚本会产生真实调用费用，CI 不运行它。

## 浏览器真实录音验证

前端录音控件在 Task 5 实现，这一步需要人工操作。在 Chrome/Edge 和 Safari 里各录 10 秒与 120 秒的中文回答，并记下实际 MIME——这是 Task 3 `AudioNormalizer` 需要接受的封装清单依据。

在目标页面的 DevTools 控制台执行：

```javascript
const mime = ['audio/webm;codecs=opus', 'audio/mp4', 'audio/ogg;codecs=opus']
  .find(t => MediaRecorder.isTypeSupported(t));
console.log('MIME：', mime || '(浏览器默认)');
const chunks = [];
const rec = new MediaRecorder(
  await navigator.mediaDevices.getUserMedia({
    audio: { channelCount: 1, echoCancellation: true, noiseSuppression: true },
    video: false,
  }));
rec.ondataavailable = e => chunks.push(e.data);
rec.onstop = () => {
  const a = document.createElement('a');
  a.href = URL.createObjectURL(new Blob(chunks, { type: rec.mimeType }));
  a.download = 'recording.webm';
  a.click();
};
rec.start(1000);
console.log('录音中，执行 stop() 停止');
stop = () => rec.stop();
```

拿到文件后按后端将要使用的同一组参数转换，确认能识别出原音频对应内容：

```bash
ffprobe -v error -show_entries format=duration -of json recording.webm
ffmpeg -nostdin -hide_banner -loglevel error -y -i recording.webm \
  -map 0:a:0 -vn -ac 1 -ar 16000 -c:a pcm_s16le out.wav
python3 backend/tools/speech-smoke.py --asr-file out.wav
```

`--asr-file` 会把文件字节原样送出，所以这里必须真正转成 WAV，**不能只把扩展名改成 `.wav`**。Chrome/Edge 通常得到 WebM/Opus，Safari 通常得到 MP4/AAC；120 秒样本用于同时验证时长上限与大小上限。

## 三个协议注意点

Task 3 实现时不能省略，冒烟阶段也要先确认：

1. **录音封装要真实转码。** 前端 `MediaRecorder` 的 `sampleRate` 参数不能证明最终音频就是 16 kHz，封装和采样率都要靠后端 FFmpeg 兜住。
2. **ASR 要同时看 HTTP 状态和 `X-Api-Status-Code`。** 静音、空音频、格式错误都是 HTTP 成功加业务状态失败；只看 HTTP 状态会把静音当成功。
3. **TTS 是逐行 JSON 流，不是可直接播放的响应。** 逐个解码 `data` 片段，`code=20000000` 才是成功结束；非零且非 0 是业务失败；没有结束事件或没有音频都不能播放半成品。

## 鉴权与资源授权

key 有效不等于资源可用，两层要分开看。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| HTTP 401，响应体没有可读信息 | key 无效或平台用错。方舟（Ark）大模型 key 以 `ark-` 开头，不能调语音接口 | 改用语音技术控制台创建的 key |
| HTTP 403，`code=45000030`，`message=[resource_id=...] requested resource not granted` | key 鉴权已通过，但账号未授权该资源 | 在控制台为对应资源开通/申请权限 |

请求头里的资源 id 和授权页上显示的不一定相同，实测映射如下。

| 请求头 `X-Api-Resource-Id` | 服务端实际资源 id |
| --- | --- |
| `seed-tts-2.0` | `volc.seedtts.default` |
| `seed-tts-1.0` | `volc.service_type.10029` |
| `volc.bigasr.auc_turbo` | 同名，但无法确认服务端是否识别 |
| `volc.seedasr.sauc.duration` | 同名 |

**ASR 资源不必非用 `volc.bigasr.auc_turbo`。** 实测已开通流式识别资源的账号，用 `volc.seedasr.sauc.duration` 调同一个 HTTP 端点 `/api/v3/auc/bigmodel/recognize/flash` 能完整走通识别，无需另开通文件识别资源。授权哪个资源取决于账号实际开通情况，冒烟脚本用 `VOLC_ASR_RESOURCE_ID` 指定，Task 3 的 `asr-resource-id` 也要按账号填写。并发版 `volc.seedasr.sauc.concurrent` 在本账号返回 `45000292 quota exceeded for types: concurrency`。

业务错误在响应体的 `header` 对象里（`{"header":{"code","message"}}`），不在顶层。TTS 的 403 不带 `X-Api-Status-Code` 头，错误只在 body；ASR 会同时带 `X-Api-Status-Code` 头和 body。响应头 `X-Tt-Logid` 用于向火山排查。

**不能用回显的 `resource_id` 判断配置是否正确。** 服务端把任何请求头里的资源 id 原样回显，包括明显不存在的值（实测 `definitely-not-a-real-resource` 同样返回 `45000030`），所以 `45000030` 分不清"资源名拼错"和"资源存在但未授权"。已知的服务端规范化线索是：`seed-tts-2.0` 会被改写成 `volc.seedtts.default`，说明它被识别；`volc.bigasr.auc_turbo` 原样回显，是否被识别无法从响应区分。Task 3 的错误提示按"资源未授权"统一处理即可，不要试图解析出正确 id。

## 已验证（协议逻辑，本地 stub）

以下协议逻辑由一次性本地 stub 验证（stub 只监听 127.0.0.1，不产生费用，不进仓库），共 19 个场景：

- 缺 `VOLC_SPEECH_API_KEY` 时脚本打印提示并退出，不发起任何网络请求；密钥在任何输出中都不出现。
- TTS 多片段音频能正确拼接；缺成功结束事件、业务失败码、非法 Base64、结束但无音频、返回 HTML 五种情况都被拒绝，且不返回半成品。
- 合成结果非 MP3 帧格式时不落盘。
- ASR 侧：业务状态非成功、HTTP 500、静音无文字、响应结构不对、缺业务状态头五种情况都被拒绝并给出可读原因。
- `--asr-file` 把文件字节原样送出，不先调 TTS；音色与 MP3 落地路径可参数化。
- 转换参数在本机产出 `pcm_s16le`、16000 Hz、单声道，时长与输入一致。
- 真实返回过的资源未授权响应（403 + `header` 嵌套错误）能被解析出人可读原因，而不是显示"上游未返回可读错误信息"。

以上覆盖协议边界与错误分支。真实端点、鉴权、音色权限与真实耗时已实测，结果见上一节「验证记录」；stub 覆盖不到真实音频质量。

## 大小与时长上限核对

120 秒 16 kHz 单声道 PCM16 WAV 实测 3.66 MiB（等于计划里写的 3.84 MB 十进制，两者一致），低于 5 MiB 上传上限；121 秒样本 3.69 MiB，同样在大小上限内，说明**大小上限拦不住超时录音**，后端必须用 FFprobe 时长校验而不是只比字节数。

保留现有 multipart 的 `5MB / 6MB` 配置，简历仍限制 5 MiB。应用侧限制为：单次录音最多 120 秒、上传最多 5 MiB、确认后的回答最多 5000 个 UTF-16 code units。
