## 0. 关键踩坑记录（这台机器特有）

推送这一步踩了两个坑，值得记下来：

**坑 1：GCM 不支持 `socks5h` 方案。**
最早我配的是 `http.https://github.com.proxy = socks5h://127.0.0.1:10808`。
git 自己的 libcurl 支持它（所以 `git clone` 成功了），但 **Git Credential Manager 是 .NET 写的，
读取同一个配置后直接崩**：

```
fatal: ServicePointManager 不支持具有 socks5h 方案的代理。
error: failed to execute prompt script (exit code 1)
fatal: could not read Username for 'https://github.com'
```

后面那句 `could not read Username` 是连锁反应：GCM 挂了之后 git 退回命令行要密码，
而后台作业没有 TTY（`/dev/tty: No such device or address`），于是彻底失败。

**坑 2：HTTP 代理只绑在 IPv6 回环上。**
本机的 HTTP 代理端口是 10809，但它只监听 `[::1]`，不监听 `127.0.0.1`：

| 地址 | 结果 |
|---|---|
| `http://127.0.0.1:10809` | ❌ 连不上 |
| `http://localhost:10809` | ✅ 通（解析到 `::1`） |
| `http://[::1]:10809` | ✅ 通 |
| `socks5://127.0.0.1:10808` | ✅ 通（但 GCM 用不了） |

**最终可用的配置**（两边都能用：libcurl 传输 + GCM 授权）：

```powershell
git config --global http.https://github.com.proxy "http://[::1]:10809"
```

**排查这类问题的正确顺序**：先把「传输」和「授权」分开。
`git ls-remote origin` 不需要凭据，能单独验证代理是否可用；

```powershell
git -c http.proxy="http://[::1]:10809" ls-remote origin
```

这一步通了，说明代理没问题，剩下的就只是凭据。

### 1.1 ⚠️ 先处理端口占用

**你机器上 8080 已经被占用了。** 实测已定位到具体是谁：

```
服务名    : NIApplicationWebServer
显示名    : NI Application Web Server
路径      : D:\Program Files (x86)\National Instruments\Shared\NI WebServer\ApplicationWebServer.exe
启动类型  : 自动      状态: 运行中
```

这是你装的 **National Instruments 软件**（LabVIEW / Multisim / NI-DAQmx 之类）的组件。

**结论：不要杀它。** 它是自动启动的服务，杀了重启后还会回来，而且可能被你其他 NI 软件依赖。
直接 `mvn spring-boot:run` 会报：

```
Web server failed to start. Port 8080 was already in use.
```

**解决办法：换端口。** `application.yml` 里写的是 `port: ${SERVER_PORT:8080}`，两种覆盖方式：

```powershell
# 方式一：环境变量（最通用，队友也能用）
$env:SERVER_PORT = 8081
mvn spring-boot:run

# 方式二：本地 profile（本机已经建好 src/main/resources/application-local.yml，内容就是 port: 8081）
mvn spring-boot:run -Dspring-boot.run.profiles=local
```

> `application-local.yml` 在 `.gitignore` 里，**不会提交**——它是本机专用的。
> 队友那台机器通常 8080 是空的，仓库默认端口保持 8080 不动。
>
> 冒烟测试也要跟着改端口：`-BaseUrl http://localhost:8081`。

## 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `Port 8080 was already in use` | 8080 被 NI Application Web Server 占用（实测如此） | 用 `$env:SERVER_PORT=8081` 或 `-Dspring-boot.run.profiles=local`。**不要杀那个服务** |
| `mvn` 不是内部或外部命令 | Maven 不在 PATH | 用 `C:\dev\tools\apache-maven-3.9.9\bin\mvn.cmd` 全路径，或先把 Maven 的 bin 加进 PATH |
| 启动时 `CSV 岗位库` 命中 0 条 | `classpath:jobs/sample-jobs.csv` 没打进 classpath | 确认 `src/main/resources/jobs/sample-jobs.csv` 存在，重新 `mvn clean` |
| 前端报 CORS 错误 | 没走代理直连后端 | 按 2.1 加 Vite 代理，或确认后端 `WebMvcConfiguration` 生效 |
| **用 PowerShell 手测接口，中文是 `å²ä½åº` 乱码** | PS 5.1 的 `Invoke-RestMethod` 在响应头缺 charset 时按 ISO-8859-1 解码 | 后端已显式声明 `charset=UTF-8`，现在不会了。若在旧版本上遇到：取原始字节自行按 UTF-8 解码，见 `smoke-api.ps1` 的 `Invoke-ApiRaw` |
| 断言里 `.Count` 明明应该是 1 却判失败 | PS 5.1 的 `ConvertFrom-Json` 会把**单元素数组拆成标量**，此时 `.Count` 不可靠 | 用 `@(...)` 包一层，见 `smoke-api.ps1` 的 `CountOf` |
| `aiUsed = false` 但你以为配了 key | key 无效 / base-url 错 / model 名错 / 额度用尽 | 看后端日志里的降级原因；401 是 key 问题，404 是 base-url 或 model 问题，429 是额度 |
| 岗位列表是空的 | 数据源全关或全挂 | 访问 `/api/jobs/sources` 看来源状态；`app.job.sources.mock-enabled` 别关 |
| 启动日志里的中文乱码 | Windows 控制台默认 GBK，与日志输出编码不一致 | 先执行 `chcp 65001` 再启动。**仅影响日志显示，不影响接口返回** |
| PowerShell 脚本报奇怪的语法错误 | PS 5.1 把无 BOM 的 UTF-8 当 ANSI 读，中文被拆坏 | 用 VS Code「以 UTF-8 with BOM 保存」重新存一次（本仓库的 `.ps1` 已带 BOM） |
| `verify.sh` 在 Git Bash 里报 `No such file or directory` | 文件被编辑器加了 BOM，shebang 失效 | **`.sh` 必须无 BOM**，`.ps1` 必须有 BOM。已在 `backend/.gitattributes` 注明 |
| `git push` / `git clone` 连接被重置 | 本机 GitHub 直连被阻断 | 走 SOCKS5 代理：`git config --global http.https://github.com.proxy socks5h://127.0.0.1:10808` |
