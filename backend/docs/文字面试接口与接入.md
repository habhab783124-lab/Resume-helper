# 简历驱动文字面试

已实现：上传 PDF/DOCX/UTF-8 TXT → 查看提取文本 → AI 根据简历提问 → 用户回答 → AI 根据历史追问 → 自动或手动结束。扫描版 PDF 需要先转换为文字，页面提供粘贴文本入口。本期不包含 TTS、评分或 AI 面试报告。

## 本地运行与模型配置

后端需要 JDK 17、Maven；前端需要 Node.js 18+。

```bash
# 终端一：在 backend/ 中运行
export AI_API_KEY='你的模型密钥'
export AI_BASE_URL='https://api.deepseek.com/v1'
export AI_MODEL='deepseek-chat'
mvn spring-boot:run

# 终端二：在 frontend/ 中运行
npm ci
npm run dev
```

在前端使用演示账号登录，进入”模拟面试”。Vite 将 `/api` 代理到 `http://localhost:8080`。如果后端端口不同，前端启动前设置 `VITE_PROXY_TARGET=http://localhost:8081`，后端设置 `SERVER_PORT=8081`。macOS Homebrew JDK 如未被系统识别，可设置 `JAVA_HOME=/opt/homebrew/opt/openjdk@17`。本机未装 Maven 时可 `brew install maven`；Maven 3.10 依赖的 JDK 版本可能高于项目要求，跑测试时建议显式指定 `JAVA_HOME=/opt/homebrew/opt/openjdk@17 mvn test`。

模型遵循 OpenAI 兼容 `chat/completions` 文本接口。简历由后端提取文本，不依赖模型厂商的文件上传接口。每轮将简历、目标岗位、历史问答提交给模型，模型只生成下一道问题。默认最多等待 60 秒；未配置密钥时返回明确提示，不使用伪造的 AI 问题。

页面的”模型设置”允许输入个人 API Key、Base URL 和模型名；密钥只在当前页面内存中，刷新需重新填写。服务端配置适合团队共享环境；密钥不要写入前端环境变量、源码或 Git。请求头 `X-AI-Api-Key` 覆盖服务端密钥，`X-AI-Model` 覆盖默认模型。仅显式提供个人密钥时，后端才接受 `X-AI-Base-Url`；服务器密钥始终发往服务器配置的地址。面板内的”测试连接”会发一次要求 10 秒内响应的极短补全来验证三项配置，失败时返回具体原因（例如密钥无效、路径不存在、超时），且不产生面试记录。

## 接口

响应统一为 `{ "success": true, "message": null, "data": ... }`，空字段可能省略。错误为 `{ "success": false, "message": "用户可读提示" }`。

| 方法与路径 | 请求 | 响应 data |
| --- | --- | --- |
| POST `/api/materials` | multipart `file` | material |
| GET `/api/materials/{id}` | 无 | material |
| POST `/api/interviews` | `{materialId,targetRole?,questionCount?}` | session，包含第一题 |
| GET `/api/interviews/{id}` | 无 | session，恢复当前题及历史 |
| POST `/api/interviews/{id}/turns` | `{questionId,answer}` | session，包含下一题或结束状态 |
| POST `/api/interviews/{id}/finish` | 无 | session，状态 FINISHED |
| POST `/api/ai/check` | 无，按 X-AI-* 请求头解析凭据 | `{model}`；凭据可用返回 200，否则按原因返回 400/502/503 |

material 示例：

```json
{"materialId":"uuid","fileName":"简历.pdf","status":"READY","text":"提取出的简历文本"}
```

session 示例：

```json
{
  "sessionId":"uuid", "materialId":"uuid", "targetRole":"Java后端", "questionCount":5,
  "status":"ACTIVE",
  "turns":[{"questionId":"uuid","question":"请介绍简历中的项目。"}],
  "currentQuestion":{"questionId":"uuid","question":"请介绍简历中的项目。"}
}
```

已回答轮次包含 `answer`。模型失败后，GET 返回 `pendingAnswer`，当前题不变；使用同一 `questionId` 和原回答重试。不同回答冲突返回 409。已经成功的回答重复提交不会再次调用模型。最后一题提交后直接结束，不额外调用模型。手动结束会保存已有待重试回答，但不会自动保存浏览器中尚未提交的草稿。

## 范围与限制

- 文件最大 5MB，PDF 最多 30 页，提取文本最多 20,000 字，回答最多 5,000 字，题数 1–10（默认 5）。追问也占一题。
- 文件同步解析，不需要轮询。无扫描 OCR；损坏、加密或无法提取的文件提示换文件或粘贴文本。
- 以服务器 `HttpSession` cookie 隔离简历和面试，客户端不能通过传 userId 获取他人记录。这是浏览器会话隔离，不是正式账号认证；同一浏览器共享 cookie 的标签页属于同一会话。
- 简历和记录仅暂存在服务器进程内，创建后一天内可访问；过期记录在后续上传/创建时清理，服务重启全部失效。每个浏览器最多暂存 20 份简历和 20 次面试，全局各 2,000。适用于单实例课程演示，后续多实例需共享存储及正式身份认证。
- 刷新通过 sessionStorage 中的面试 ID 恢复；不持久化简历正文、回答或模型密钥到浏览器存储。模型响应返回前关闭页面，首次创建可能产生无法恢复的会话；可重新开始。
- 生产部署优先使用同域反向代理 `/api`。Vercel 仅发布静态前端不会自动启动 Java 后端。`VITE_API_BASE_URL` 可指定后端 origin（不包含 `/api`），但跨域部署还需配置后端允许的精确 origin 和会话 cookie 策略；当前默认仅允许 localhost/127.0.0.1 开发来源。

## 验证

```bash
cd backend
mvn test                 # 解析、状态机、HTTP 接线、会话隔离、模型兼容传输
bash tools/verify.sh      # 原有岗位模块 102 项离线断言，仅验证岗位模块

npm test
npm run build
```

测试用本地可控模型响应验证网络协议，不消耗真实模型额度。真实厂商的密钥、额度、可用模型及回答质量仍须在配置后实测。

文件解析实现参考 [Apache PDFBox 3 迁移说明](https://pdfbox.apache.org/3.0/migration.html) 和 [Apache POI 文本提取文档](https://poi.apache.org/text-extraction.html)。
