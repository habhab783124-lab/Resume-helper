# 简历驱动的文字与语音面试

已实现：上传 PDF/DOCX/UTF-8 TXT 或粘贴文本 → 核对材料原文 → 固定12道主问题+1道Hot100算法题（主问题最多两次追问） → 文字作答或录完转写 → 预览、编辑、确认提交 → 下一题 → 自动或手动结束 → 面试报告。扫描版 PDF 无文字层时需粘贴文本。语音为可选能力，接入说明见[语音面试接口与接入](语音面试接口与接入.md)。

## 本地运行与模型配置

后端需要 JDK 17、Maven；前端应用需要 Node.js 18+，自包含浏览器验证脚本需要 Node.js 24+。

```bash
# 终端一：在 backend/ 中运行
export AI_API_KEY='你的模型密钥'
export AI_BASE_URL='https://api.deepseek.com/v1'
export AI_MODEL='deepseek-chat'
mvn spring-boot:run

# 终端二：在 frontend/ 中运行
npm ci
npm run dev
```

演示登录后进入“模拟面试”。Vite 将 `/api` 代理到 `http://localhost:8080`。后端换端口时，前端启动前设置 `VITE_PROXY_TARGET=http://localhost:8081`，后端设置 `SERVER_PORT=8081`。macOS Homebrew JDK 可用 `JAVA_HOME=/opt/homebrew/opt/openjdk@17` 指定。

模型遵循 OpenAI 兼容 `chat/completions` 文本接口。后端提取简历原文，每轮把原文、岗位和问答历史发给模型，最多等待 60 秒。出题需要有效模型密钥；未配置时明确报错，不生成伪造问题。连接测试发一次最长 10 秒的短补全。

页面可设置个人 API Key、Base URL、模型名。三项配置通过共享请求上下文保存在当前标签页内存与 sessionStorage，材料、简历、面试和报告共用，支持同标签页刷新；不进入 URL、localStorage 或后端存储。请求时 `X-AI-Api-Key`、`X-AI-Model` 覆盖服务端默认值。仅提供个人密钥时接受 `X-AI-Base-Url`，且地址须符合后端允许的 HTTPS origin 清单；服务端密钥始终发送到服务端配置地址。恢复、结束和语音接口不携带文本模型设置。火山语音凭据只由后端配置。

## 接口

普通成功响应为 `{ "success": true, "data": ... }`，错误为 `{ "success": false, "message": "用户可读提示" }`。TTS 成功响应单独返回二进制 MP3。

| 方法与路径 | 请求 | 响应 data |
| --- | --- | --- |
| POST `/api/materials` | multipart `file` | `{material, extraction, text}` |
| GET `/api/materials/{id}` | 无 | `{material, extraction, text}` |
| POST `/api/interviews` | `{materialId,targetRole?}`（兼容旧questionCount输入但固定13题） | session，含第一题 |
| GET `/api/interviews/{id}` | 无 | session，恢复当前题及历史 |
| POST `/api/interviews/{id}/turns` | `{questionId,answer}` | session，下一题或 FINISHED |
| POST `/api/interviews/{id}/finish` | 无 | FINISHED session |
| GET `/api/interviews/{id}/report` | 文本模型请求头（仅首次实际评分需要） | 报告；缓存后刷新复用；ACTIVE 返回 409 |
| POST `/api/interviews/{id}/report/retry` | 文本模型请求头（仅存在待评分题时需要） | 只重试未成功评分题，保留已成功评估 |
| POST `/api/ai/check` | 文本模型请求头 | `{model}`；错误为 400/502/503 |

材料详情示例（结构化抽取结果可为空）：

```json
{"material":{"id":"mat-uuid","fileName":"简历.pdf","status":"TEXT_EXTRACTED"},"text":"提取出的原文"}
```

前端映射 `material.id → materialId`，保留文件名、状态与原文；不能把 `extraction.profile` 当作面试简历。SCANNED 或空原文提示粘贴，不能开始面试；已删除材料返回原接口错误。

```json
{
  "sessionId":"uuid", "materialId":"mat-uuid", "targetRole":"Java后端", "questionCount":13,
  "status":"ACTIVE",
  "turns":[{"questionId":"uuid","question":"请介绍简历中的项目。"}],
  "currentQuestion":{"questionId":"uuid","question":"请介绍简历中的项目。"},
  "questionMetadata":{"uuid":{"competency":"项目实现","importance":"CORE","difficulty":"BASIC","weightUnits":12,"weightReason":"岗位核心能力","kind":"MAIN","parentQuestionId":null,"mainQuestionIndex":1,"algorithm":null,"weightPercent":80.00}}
}
```

`questionMetadata` 每项包含 `kind`（MAIN/FOLLOW_UP/ALGORITHM）、`parentQuestionId`（仅追问）、`mainQuestionIndex`（主问题1–12，算法13，追问继承父题）。算法题还包含 `algorithm:{id,title,url,difficulty}`，来源为随版本发布的 [Hot100目录](../src/main/resources/interview/hot100.json)，官方目录链接为 https://leetcode.cn/studyplan/top-100-liked/ 。会话创建时随机选定并冻结题目身份；生成失败重试不换题，无运行时LeetCode网络依赖。服务端要求模型生成忠实的原创简明题意、示例与约束，显示官方标题与链接；回答可包含代码或伪代码，无代码执行。

已回答轮次带 `answer`。下一题生成失败时，GET 返回 `pendingAnswer`，当前题不变；使用同题同回答重试，改变回答返回 409。已经成功的同回答重复提交不会再次调用模型。最后一题提交直接完成，不额外出题。录音转写只生成独立预览，替换/追加/保留后仍须显式提交回答。

有本地草稿或未确认预览时，结束面试提供提交后结束、放弃草稿并结束、继续作答。未确认转写不能直接提交后结束；提交失败不跳转。服务端 pending 或结果尚未确认的提交有单独的“保留已收到回答并结束”选项：结束不能撤回服务端已收到的回答。自动完成和恢复 FINISHED 都有查看报告入口；报告路由只传 sessionId。导出按钮调用浏览器打印并展开逐题明细。

## 逐题加权报告

出题时同一次模型调用返回问题与五维标准，服务端校验后在用户作答前冻结能力、重要性、难度、相对权重及标准。Session 的 `questionMetadata` 以 `questionId` 为键，公开能力、分类、权重、题目种类、父题、序号和算法元信息，完整 `criteria` 不进入活跃面试响应。界面与 TTS 只使用问题正文；语音按用户确认提交的文字评分。

重要性为 CORE/RELATED/SUPPLEMENT，难度为 BASIC/INTERMEDIATE/ADVANCED。数字系数由后端 `InterviewScoringPolicy` 决定。出题前冻结分类和标准；全部已发出的主问题（包含尚未回答的根题）共享80.00%，算法题固定20.00%。追问无独立权重，沿用父题冻结标准联合评估。无目标岗位时，权重原因说明由简历方向推断。回答好坏和措辞不改变已有题的分类或权重。

结束后模型按冻结标准提供切题与正确性、关键要点覆盖、推理与取舍、证据与具体性、表达结构五维档位（各 0/5/10/15/20），服务端计算题分及加权总分。综合分仅在全部13道根题作答并评估成功后提供，公式为 `round(0.8 × Σ(主问题分 × weightUnits) / Σ(主问题weightUnits) + 0.2 × 算法分, 1)`，使用原始权重点数；展示百分比保留两位小数，不参与总分计算。只供本轮训练参考，没有外部校准，不代表招聘结论或整份简历掌握程度；未覆盖能力不推断为不足。

报告新增字段：

| 字段 | 含义 |
| --- | --- |
| `reportStatus` | COMPLETE / PARTIAL / UNAVAILABLE / EMPTY |
| `scoringVersion` | 服务器评分策略版本 |
| `plannedCount` / `answeredCount` / `scoredCount` | 计划根题数（13）/ 已答根题数 / 成功评分根题数 |
| `overallScore` | 全部13道根题作答且成功评估时为加权分，否则为 null |
| `turnFeedbacks` | 按根题顺序的报告，以 `questionId` 关联；追问嵌入父题 `followUps` |

逐题保留 `index`、`question`、`highlight`、`improvement`，并包含 `questionId`、`answer`、`status`、`competency`、`importance`、`difficulty`、`weightUnits`、`weightPercent`、`weightedContribution`、`weightReason`、`dimensionScores`、`evidence`、`missingPoints`、`suggestedOutline`、`aiModel`。`score` 是可空整数，零分是有效评分；原题与原回答取自服务端会话。根题还包括 `kind`、`mainQuestionIndex`、`algorithm` 和 `followUps:[{questionId,question,answer}]`。证据仅使用本组主回答或某条自己的追问回答的非空连续原文片段，不能跨回答边界拼接或引用别组，没有有效支持时允许空证据；反馈和框架只组织真实事实，不编造指标或经历。

| 状态 | 返回与展示 |
| --- | --- |
| COMPLETE | 全部已答根题成功评估；只有13题齐全才有综合分，提前结束仍为null并说明缺失的主问题与算法题 |
| PARTIAL | 部分题成功，保留已有评分，其余待评分，总分 null |
| UNAVAILABLE | 有回答但暂无成功评分，保留问答，总分 null |
| EMPTY | 没有回答，总分 null，说明无可评分内容 |

逐题 `status` 为 SCORED/PENDING/UNANSWERED。PENDING 的 `score` 和 `weightedContribution` 为 null；UNANSWERED 无分数、`weightedContribution` 为 null，保留其主问题或算法预算权重，不作为零分计入。提前结束不将缺失算法的20%重新分配。模型未配置、调用失败或格式非法都不返回默认 75 分和猜测的优缺点。

每次模型调用最多评估五组根题（8192-token输出预算），完整13题分批处理；后续批次失败保留前面成功结果。GET 首次生成后缓存报告，刷新不再次调用模型；POST retry 只请求未成功评估的题。成功评估按 `questionId` 保存，修改 skill 或模型配置后仍保持原值。评分调用才解析模型凭据，已有缓存和无回答报告不要求有效模型配置。HTTP 加载失败时重试 GET；已取得报告但评分未齐时显式 POST retry，失败仍保留已显示的报告与原问答。两个报告接口均验证当前用户归属和 FINISHED 状态；不同用户返回 404，ACTIVE 返回 409。

项目扩展及阶段加载见 [interview skill 接入说明](../../skills/interview/README.md) 和 [上游来源与校验](../../skills/interview/UPSTREAM.md)。规则文件热更新仅作用于下一次相应阶段请求，已冻结契约优先于后来修改的默认指导。报告与评估缓存共用原会话生命周期，均在进程内，重启不能恢复。

## 身份、存储与限制

- 材料、面试、ASR、TTS 与报告统一通过 `UserContext` 读取 `X-User-Id`，前端当前固定为 `demo-user`，缺省也为该值。不同值分区，但客户端可伪造，**不是正式认证或权限控制**；cookies/HTTP session ID 不决定数据归属。多用户接口联调须始终使用相同请求头。
- 面试上传区接受 PDF/DOCX/TXT，单文件最多 **10 MiB**；Spring 全局 multipart 配置为 `10MB` 文件 / `12MB` 请求（Spring DataSize 的 MB 为 1024² 字节）。语音单独限制 **5 MiB / 120 秒**，不能把材料限制改成语音限制。
- 回答最多 5000 个 UTF-16 code units，固定13道根题（12主问题+1算法题，追问不占配额），岗位最多 200 字。粘贴框最多 20,000 字；扫描件无 OCR，需要手动粘贴。
- 材料与简历版本使用本机文件系统；面试记录使用进程内存，一天内有效，后端重启失效。每个用户分区最多 20 次暂存面试，全局 2000；材料并非按面试的一天期限清理。
- sessionStorage 保存面试 ID 与标签页模型配置；本地录音、转写预览、未提交草稿不保存，刷新会丢失。首题创建响应返回前离页可能无法恢复该次会话。
- 生产优先同域 `/api` 反向代理。前端静态部署不会启动 Java 后端。跨域使用 `VITE_API_BASE_URL`（后端 origin，不含 `/api`）须配置允许来源；语音入口须 HTTPS 或 localhost。转写客户端默认 90 秒，覆盖两个各 10 秒的工具预算与 ASR 60 秒，代理超时至少 100 秒。
